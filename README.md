# 第一球 First Pitch

> 棒球，是从这里长出来的。

在线使用：<https://ChiTsng.github.io/FirstPitch/>

零基础中文读者的交互式棒球规则入门。从「一个人抛球 → 两个人抛接 → 三个人攻守」这个原型出发，
每加一条规则都是为了堵住上一层露出来的漏洞，最后收敛成五条原理。术语附日语与英语。

---

## 怎么跑起来

需要 Node.js 18 以上（本机装的是 24.19.0）。

```bash
npm install     # 第一次
npm run dev     # 开发服务器，打开它打印的 http://localhost:5173
```

其他命令：

| 命令 | 做什么 |
|---|---|
| `npm run dev` | 开发服务器，改文件自动刷新 |
| `npm test` | 跑规则引擎的测试（交接文档 T1–T19 全在里面） |
| `npm run test:watch` | 边改边跑测试 |
| `npm run typecheck` | 只做类型检查，不构建 |
| `npm run build` | 生成 `dist/`，静态文件，可以直接丢到 GitHub Pages / Netlify / Vercel |
| `npm run preview` | 本地预览构建出来的 `dist/` |

构建用的是相对路径（`base: './'`）加 hash 路由（`#/quiz`），所以 `dist/` 放在
任何子目录下都能用，不需要服务器做重写规则。

## 发布到 GitHub Pages

```bash
npm run deploy
```

此命令先构建，再将 `dist/` 单独提交到 `gh-pages` 分支。GitHub Pages 配置为从该分支的根目录发布，推送后自动更新网站。需要本机已登录 GitHub，并拥有仓库推送权限。

发布脚本使用独立的临时 Git 索引和 GitHub 隐私邮箱，不切换当前分支，也不把开发文档、截图或本地配置复制到网站。修改完成后先提交源码，再执行发布命令，方便追踪成品对应的版本。

## 想改内容，改哪里

**所有文字都在 `src/content/`，不用碰代码。**

| 文件 | 内容 |
|---|---|
| `layers.ts` | 主线第 0–5 层的全部正文（漏洞 → 规则） |
| `quiz.ts` | 题库，含选项、答案、延伸 |
| `glossary.ts` | 中日英术语表 + 易错对照 |
| `principles.ts` | 五条原理 + 元原理 + 它们推出的规则 |
| `explanations.ts` | 规则引擎每种判断对应的中文解释 |
| `lab.ts` | 情境模拟器的「会发生什么」文字 |
| `dilemmas.ts` | 两难演示的脚本（内野高飞必死、两出局满垒 3-2） |
| `timing.ts` | 时间数据与赛跑计时的场景 |
| `tactics.ts` | 常见战术 |
| `people.ts` | 人员、打序、DH、换人 |
| `liveDead.ts` | 活球与死球 |
| `stories.ts` | 规则背后的故事、ABS |
| `fielders.ts` | 9 个守备位置的中日英名称与职责 |

正文里能用的标记只有两种，故意做得很小：

```
**粗体**          强调
[[本垒打]]        术语，自动挂上日英对照的悬停提示
[[术语|显示文字]]  同上，但正文里显示别的字
```

术语要先在 `glossary.ts` 里有这一条，`[[…]]` 才会生效；没有的话就原样显示，不会报错。

**改配色**只改 `src/styles/tokens.css`。夜场（深色）和日场（浅色）两套值都在那里，
每一条都过了 4.5:1 的对比度。

## 代码是怎么分层的

```
src/
  engine/        规则引擎。纯函数，不认识 React，也不含中文文案。
    types.ts       数据模型 + 理由代码
    count.ts       球数：好球、坏球、界外、三振、保送、不死三振
    force.ts       强迫链、保送、本垒打分数、可盗的垒
    outs.ts        内野高飞必死、第三出局与得分、高飞牺牲打
    __tests__/     T1–T19 与准确性清单的测试
  content/       全部文字（见上表）
  components/    交互组件
    field/         生长的球场（SVG）与它的几何计算
  pages/         各个页面
  hooks/         主题、hash 路由、滚动取景、localStorage
  styles/        设计 token 与样式
```

**为什么引擎和文案分开**：引擎只回答「按规则会发生什么」，返回一个理由代码
（比如 `'strike.foulCapped'`）；界面拿这个代码去 `explanations.ts` 取中文。
这样改措辞不会弄坏逻辑，改逻辑也不会牵动一堆文案，而且规则判断可以直接写测试。

**球场的几何是真的**：`components/field/geometry.ts` 里全部按米计算 ——
垒间 27.43 m、投手板到本垒 18.44 m、界线夹角 90°、跑垒道宽 0.9 m。
所以图上的比例关系可以直接拿来讲道理。

## 规则准确性

准确性优先于视觉效果。交接文档第 8 节的易错清单逐条对照过，其中能写成断言的
（强迫链、第三出局得分、不死三振的限制、内野高飞必死的适用条件、2 好球后的界外……）
都在 `src/engine/__tests__/engine.test.ts` 里，`npm test` 一次跑完。

带 ⏱ 的时效性事实（MLB／NPB 的 DH、投球计时与牵制次数、ABS 挑战系统及其第一个
赛季的数据、中央联盟 2027 年起采用 DH）核对于 **2026 年 9 月**。联盟规则每年都可能
变动，引用前请再确认一次。

页面里不使用任何球队、联盟的标志、吉祥物或真实球员肖像；插画只有通用的剪影人物。

## 无障碍与移动端

- 键盘可达，焦点用照明金描边，任何主题下都看得见；开头有「跳到主要内容」。
- 每个球场 SVG 都带 `<title>` 描述当前局面；记分板和解释条用 `aria-live` 播报变化。
- 两套主题的正文、次要文字、强调色、按钮文字全部 ≥ 4.5:1。
- 尊重 `prefers-reduced-motion`：系统开启时停止氛围循环、击球直接显示结果；默认使用完整动效。
- 移动端观察室位于章节阅读段前，导航可展开；宽表格自己横向滚动，页面本身不横滚。
